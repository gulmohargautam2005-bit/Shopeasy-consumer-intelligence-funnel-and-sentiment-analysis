1. Data Validation Phase (01.Data_Validation.sql)

Audit checks performed over dimensions and fact tables to inspect data quality before downstream ingestion.

A. Customer Journey Table (customer_journey)

1. Null Check Query

Checks columns for NULL entries using a single-pass sum aggregation.

SELECT 
    COUNT(*) AS total_rows,
    SUM(CASE WHEN CustomerID IS NULL THEN 1 ELSE 0 END) AS null_customer_id,
    SUM(CASE WHEN ProductID IS NULL THEN 1 ELSE 0 END) AS null_product_id,
    SUM(CASE WHEN VisitDate IS NULL THEN 1 ELSE 0 END) AS null_visit_date,
    SUM(CASE WHEN Stage IS NULL THEN 1 ELSE 0 END) AS null_stage,
    SUM(CASE WHEN Action IS NULL THEN 1 ELSE 0 END) AS null_action,
    SUM(CASE WHEN Duration IS NULL THEN 1 ELSE 0 END) AS null_duration
FROM dbo.customer_journey;
Duration NULL Verification 613 NULLs were identified in the Duration column. Further grouping queries confirmed all NULL durations occur exclusively during page "Click" drop-offs, indicating this is expected transactional behavior.

2. Logical Duplicate Check

Detects repeated customer-product interactions at identical points in time.

WITH duplicates AS (
    SELECT 
        JourneyID, CustomerID, ProductID, VisitDate, Stage, Action, Duration,
        ROW_NUMBER() OVER (
            PARTITION BY CustomerID, ProductID, VisitDate, Stage, Action 
            ORDER BY JourneyID 
        ) AS rnk 
    FROM customer_journey
)
SELECT * FROM duplicates 
WHERE rnk > 1;

3. Case-Sensitive Collation Auditing

Exposes casing variations hidden by default Case-Insensitive configurations in SQL Server.

SELECT DISTINCT Stage COLLATE Latin1_General_CS_AS FROM dbo.customer_journey;
SELECT DISTINCT Action COLLATE Latin1_General_CS_AS FROM dbo.customer_journey;

2. Data Cleaning & Transformation Phase

Resolves issues identified in validation by outputting clean tables.

A. Deduplication & Materialization

Selects unique customer actions (filtering `rnk = 1`) and creates the cleaned table.

WITH duplicates AS (
    SELECT 
        JourneyID, CustomerID, ProductID, VisitDate, Stage, Action, Duration,
        ROW_NUMBER() OVER (
            PARTITION BY CustomerID, ProductID, VisitDate, Stage, Action 
            ORDER BY JourneyID 
        ) AS rnk 
    FROM customer_journey
)
SELECT JourneyID, CustomerID, ProductID, VisitDate, Stage, Action, Duration
INTO dbo.customer_journey_cleaned
FROM duplicates
WHERE rnk = 1;

B. Column Splitting & Standardizing (engagement_data)

Splits views and clicks from `ViewsClicksCombined` and standardizes text strings.

SELECT 
    EngagementID,
    ContentID,
    CASE 
        WHEN UPPER(ContentType) = 'BLOG' THEN 'Blog'
        WHEN UPPER(ContentType) = 'SOCIALMEDIA' THEN 'Socialmedia'
        WHEN UPPER(ContentType) = 'VIDEO' THEN 'Video'
        WHEN UPPER(ContentType) = 'NEWSLETTER' THEN 'Newsletter'
        ELSE ContentType
    END AS ContentType,
    Likes,
    CONVERT(date, EngagementDate) AS EngagementDate,
    CampaignID,
    ProductID,
    CONVERT(int, LEFT(ViewsClicksCombined, CHARINDEX('-', ViewsClicksCombined) - 1)) AS Views,
    CONVERT(int, RIGHT(ViewsClicksCombined, LEN(ViewsClicksCombined) - CHARINDEX('-', ViewsClicksCombined))) AS Clicks
INTO dbo.engagement_data_cleaned
FROM [dbo].[engagement_data];
String Manipulation Mechanics CHARINDEX finds the hyphen separator index. LEFT grabs characters before the index to extract views. RIGHT calculates the remaining length to fetch clicks. Both values are cast to INT to allow calculation of Click-Through Rates (CTR).

1. Sentiment Scoring & Lexicon Rescuing

Processes text reviews using the VADER lexicon package, integrated with Star Rating logic to circumvent lexical shortcomings.

A. Python Sentiment Scoring Run

from vaderSentiment.vaderSentiment import SentimentIntensityAnalyzer

analyzer = SentimentIntensityAnalyzer()
df_reviews['SentimentScore'] = df_reviews['ReviewText'].apply(
    lambda x: analyzer.polarity_scores(x)['compound']
)

B. The Hybrid Sentiment Model

Corrects e-commerce phrases (like "The quality is top-notch") which VADER ranks as neutral (`0.0`), by utilizing the customer’s rating as a fallback validator.

def categorize_sentiment(score, rating):
    if score > 0.05: 
        if rating >= 4:
            return 'Positive'  
        elif rating == 3:
            return 'Mixed Positive'  
        else:
            return 'Mixed Negative'  
    elif score < -0.05: 
        if rating <= 2:
            return 'Negative'  
        elif rating == 3:
            return 'Mixed Negative' 
        else:
            return 'Mixed Positive'  
    else:  # VADER Compound Score = 0.0 (Neutral)
        if rating >= 4:
            return 'Positive'  # Rescue positive gap
        elif rating <= 2:
            return 'Negative'  # Rescue negative gap
        else:
            return 'Neutral'
Mixed Negative Categorization Identifies customers who leave a rating of 3 but include negative text context. Standard rating aggregates miss this group, making them high churn risks.

2. Negative Theme Extraction & Key Frequency

Filters negative review texts and extracts specific complaint themes.

A. Tokenization & Stop-word Filtering

from collections import Counter
import re

df_negative = df_reviews[df_reviews['SentimentCategory'] == 'Negative']
negative_text = ' '.join(df_negative['ReviewText'].str.lower())
words = re.findall(r'\b\w+\b', negative_text)

stop_words = ['the', 'a', 'is', 'it', 'was', 'and', 'for', 'to', 'of', 'my', 'i', 'not', 'very', 'this']
filtered = {w: c for w, c in Counter(words).items() if w not in stop_words}
print(Counter(filtered).most_common(5))
